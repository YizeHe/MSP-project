就是你说的 “数据包对邻居广播、层层扩散” 的标准专业名词：

循环防护：用数据包唯一 ID + 本地缓存过滤重复包，避免无限广播风暴；
优势：零路由表维护、拓扑完全灵活，不存在 “路由失效”，只要网络存在任意连通路径就能送达。

全网 MAC 是唯一的吗
分两层完整解答：本地网段唯一，全网不唯一
一、MAC 地址基础定义
MAC（媒体访问控制地址）是网卡硬件标识，长度 48 位，格式 XX:XX:XX:XX:XX:XX，分为两段：
前 24 位（OUI）：厂商组织唯一标识符，IEEE 分配给硬件厂商；
后 24 位：厂商自行分配给每一块网卡。
二、核心唯一性规则
1. 出厂理想状态：同厂商同批次硬件无重复
正规厂商出厂时，会保证自家产出网卡的后 24 位不重复，理论上全球所有网卡 MAC 互不重复。
2. 现实场景：全网 MAC 不唯一（大量重复情况）
（1）软件篡改 MAC（MAC 伪装 / 随机 MAC）
系统、虚拟机、随身 WiFi、隐私工具都支持修改 MAC 地址：
Windows/macOS/Linux 可手动自定义任意 MAC；
手机随机 MAC、VMware 虚拟网卡自定义 MAC；
攻击者、隐私工具会批量复用相同 MAC，直接造成全网重复。
（2）虚拟设备批量复用 MAC
云服务器、容器、虚拟机常配置相同虚拟 MAC；
路由器 AP、物联网模组出厂批量复用默认 MAC。
（3）IEEE OUI 分配漏洞 / 山寨硬件
廉价杂牌网卡、二手翻新设备，厂商未向 IEEE 申请 OUI，直接复制其他品牌 MAC，全网大量冲突。
3. 通信层面仅要求「二层网段内唯一」
MAC 只工作在局域网二层（交换机 / 内网）：
同一局域网内，两台设备 MAC 重复会直接断网、ARP 冲突；
跨公网、跨不同城市 / 国家的网段，MAC 重复完全不影响通信 —— 公网路由只识别 IP，不会转发 MAC 地址。
三、关键区分误区
❌ 误区：MAC 是全球唯一硬件身份证
✅ 事实：仅原厂合规未修改的物理网卡理论唯一；只要人为修改、虚拟设备、山寨硬件，全网必然出现大量重复 MAC。
❌ 误区：互联网会校验 MAC 唯一性
✅ 事实：MAC 不会跨路由器传输，公网根本看不到对端设备的 MAC，不存在全网校验机制。
四、和你之前 DTN / 匿名网络场景关联
你描述的泛洪广播 DTN 网络，底层可随机化 MAC 规避追踪，刻意制造重复 MAC；
国内 DPI 流量监测会采集 MAC 作为设备指纹，但 MAC 可随意篡改，无法作为长期身份锚点；
瑞士隐私法规允许用户修改、随机化 MAC，属于合法隐私保护行为。

原厂未篡改的物理网卡：理论全球唯一；
现实互联网全网：MAC 不唯一，篡改、虚拟设备、山寨硬件会大量产生重复 MAC；
网络通信约束：仅同一局域网内 MAC 必须唯一，跨网段无唯一性要求。

二、为什么不能 100% 绝对唯一（理论边界）
1. 同一纳秒多设备并发采样（最核心碰撞场景）
两台及以上设备在完全相同的纳秒时刻读取系统时间作为 Seed 输入：
输入原文完全一致 → SHA-256 哈希结果必然完全相同，直接产生碰撞；
现代 CPU、集群、分布式网络中，多机同步时钟（NTP）精度可达纳秒级，存在同时采样的客观可能性。
2. SHA-256 本身存在 “生日悖论” 碰撞风险
密码学哈希无法做到 “输入唯一→输出唯一”，仅满足单向不可逆 + 抗人为构造碰撞；
根据生日悖论，当生成约 
2128
 个哈希值后，出现随机碰撞的概率会超过 50%。
但纳秒时间戳的总取值上限极低：
以 100 年时间窗口计算，总纳秒刻度仅 
100×365×24×3600×109≈3.15×1018
，远小于 
2128
，随机自然碰撞概率可以忽略。
3. 系统时钟回滚 / 跳变漏洞
系统时间被手动修改、NTP 校准跳回过去时间，会复用历史纳秒时间戳，重复输入产生相同哈希。
三、工程层面：如何做到 “几乎绝对唯一”（规避碰撞）

叠加设备本地随机熵（推荐）

叠加硬件不可变片段
叠加 CPU 微码 ID、硬盘序列号（仅本地读取，不对外暴露），多设备同一纳秒采样时输入也会不同；
叠加设备公钥哈希
结合你之前关注的加密身份体系，用本机 Ed25519 公钥哈希作为附加输入，全局无重复。

BTC 私钥是以什么为种子生成的
搜索 3 个关键词，参考 18 篇资料
分两条主线讲清：原生单私钥、HD 分层钱包私钥，二者「种子」来源完全不同
一、基础：比特币单私钥（非 HD，中本聪早期挖矿用的类型）
1. 它没有 “衍生种子”，直接靠密码安全熵（CSPRNG 随机源） 生成私钥本体
私钥本质是 1 ~ secp256k1阶数n 之间的 256 位随机整数，输入熵就是唯一原始素材，不存在固定预设 seed 字符串。
Bitcoin Core 官方随机熵混合来源（多源叠加，避免单一熵失效）：
硬件真随机源
CPU 内置 RDSEED/RDRAND 硬件 TRNG、CPU 纳秒周期计数器 RDTSC；
操作系统内核安全随机池
Linux /dev/urandom / getrandom、macOS getentropy、Windows CryptGenRandom；
动态事件噪声
鼠标移动延迟、磁盘 IO 耗时、网络数据包纳秒时间戳、进程调度时差；
软件内置混淆
全部素材送入 SHA512 做混合，输出均匀 256 位数字作为私钥。
关键：早期中本聪 2009 挖矿私钥
当年 Bitcoin Core 0.1 版本用完全相同的多源系统熵生成，仅靠系统硬件 + 时间噪声，无助记词、无预设字符串 seed。
二、现代 HD 分层钱包（BIP32+BIP39，现在 99% 钱包使用）
这是大家常说 “有 seed 助记词” 的体系，分两级种子：
层级 1：原始熵（Entropy，底层真随机素材）
12 词助记词 = 128 位熵；24 词 = 256 位熵；
同样由系统 CSPRNG 硬件 / 事件随机生成，这是一切的源头，和单私钥熵源一致。
层级 2：助记词 Seed（Mnemonic Seed）
熵经过 BIP39 编码成单词，再可选加盐（passphrase），用 PBKDF2-HMAC-SHA512 拉伸得到512 位主种子 S。
层级 3：HD 主私钥（从 S 派生）
BIP32 标准固定推导公式：
I = HMAC-SHA512(Key="Bitcoin seed", Data=S)
I 左 32 字节 = 主私钥；
I 右 32 字节 = 链码（用于派生子私钥）。
这里的字符串 "Bitcoin seed" 只是 HMAC 的固定密钥，不是生成私钥的随机种子，极易混淆。
三、纠正两个高频误区
❌ 误区：私钥 seed 是纳秒时间戳
✅ 事实：时间戳只是众多熵源之一，不能单独作为种子，只用时间会出现碰撞、可暴力破解；必须叠加硬件真随机、系统噪声。
❌ 误区："Bitcoin seed" 是生成私钥的种子
✅ 事实：这是固定 HMAC 密钥，用来拉伸 HD 主种子；真正决定私钥唯一性的是用户本地随机生成的熵 / 助记词种子。
四、完整流程极简对比
老式单私钥（中本聪挖矿）
多源硬件 / 时间噪声熵 → SHA512 混合 → 256 位数字 = 私钥
无中间字符串 seed，熵直接等于私钥原料。
现代 HD 钱包（助记词）
硬件随机熵 → BIP39 助记词 → PBKDF2 拉伸得到 512 位主种子 S → HMAC-SHA512 ("Bitcoin seed", S) → 主私钥 → 子私钥

二、必须解决的两大致命缺陷（单纯 CSPRNG+时间→SHA256=私钥 的漏洞）
1. SHA256 输出不能直接当椭圆曲线私钥（规范约束）
secp256k1、Ed25519 等曲线有严格值域限制：
以 Ed25519 为例：标准流程不是直接拿哈希当私钥，而是对哈希做固定位裁剪、序列化处理；
secp256k1 私钥要求数值小于曲线阶数 n = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141；
SHA256 输出是 0~2²⁵⁶-1 的均匀随机数，存在极小概率输出值 ≥ n，此时直接使用会非法，必须重新采样熵生成。
修复方案：哈希后做模曲线阶校验，超出范围则重新采集熵循环生成。
2. 时间戳仅作为辅助熵，不能作为可靠熵源兜底
极端场景风险：
系统时钟冻结、NTP 强制同步锁死时间，时间熵失去变化性；
无硬件随机源的低配设备（老旧 VPS、嵌入式设备），内核urandom熵池枯竭，仅靠时间会导致熵不足，私钥存在暴力枚举风险。
标准安全设计：时间仅作为附加混淆噪声，核心熵源必须是密码安全 CSPRNG，时间熵权重极低，仅用来增加多样性，不承担随机性主力。

HD 派生规则：HMAC-SHA512 ("MST seed", 助记词拉伸种子)，仅一条硬化路径生成本节点长期 Ed25519 身份密钥，无其他派生分支。
1.3 身份密码学基础
长期身份：Ed25519 签名密钥 + X25519 DH 密钥（同一组密钥复用）
公钥哈希 SHA1 作为全网节点唯一标识 ID；
无内置密钥、无 CA、无中心化证书。
模块 2：完整中间人攻击防护协议（X3DH 定制改良，适配 DTN 泛洪网络）
前置前提
网络无中心服务器，公钥通过全网泛洪广播扩散，不存在单点公钥劫持；搭配三层防御彻底阻断 MITM。
三层防护体系
第一层：X3DH 端到端会话密钥协商（核心）
用户本地预生成批量一次性 X25519 预密钥 OPK，全部用自身长期 Ed25519 私钥签名；
发送方发起通信时，全网广播请求目标节点公钥 + 签名预密钥集合；
双方四组 DH 复合计算共享密钥：
DH1 = DH (发送方身份私钥，接收方签名预公钥)
DH2 = DH (发送方临时私钥，接收方身份公钥)
DH3 = DH (发送方临时私钥，接收方签名预公钥)
DH4 = DH (发送方身份私钥，接收方一次性预公钥)
四组 DH 输出拼接后 SHA512 生成唯一会话密钥，仅用于加密消息载荷；
每一条消息附加会话密钥生成的 MAC，防止载荷篡改。
第二层：全网公钥泛洪校验
任意节点收到陌生公钥，自动向全网广播该公钥副本；全网节点缓存已知合法公钥哈希，若出现同一 ID 对应两条不同公钥，标记为中间人伪造，自动丢弃两条消息，同时推送本地告警。
第三层：带外指纹核验（用户手动兜底）
身份公钥 SHA1 截断为 16 位短指纹，双方可线下核对；指纹不匹配则拒绝建立任何会话，彻底阻断长期 MITM 劫持。
中间人攻击失效逻辑
攻击者无法同时替换双方公钥：泛洪网络会同步两份冲突公钥，全网识别异常拦截；即使劫持单次公钥，X3DH 多重 DH 组合缺少对方长期私钥，无法生成有效会话密钥，无法解密任何消息载荷。
模块 3：DTN 数据包完整结构（元数据明文、仅载荷加密，携带全所需字段）
数据包整体分层：明文头部（路由 / 元数据） + AES-256-GCM 加密载荷
明文头部（全部节点可读，不可篡改，附带全局 SHA1 数据包哈希）
Packet_SHA1：整条数据包（头部 + 密文载荷）的 SHA1 哈希，数据包唯一标识，用于本地 65536 条缓存去重
Timestamp_μs：发送端本地微秒级时间戳（主排序依据）
Sender_ID：发送方公钥 SHA1（明文）
Target_ID：接收方公钥 SHA1（单播）/ Broadcast_Flag=1（全网广播）
Alert_Flag：布尔值，true = 全网公告（Alert 私钥签名），false = 普通用户消息
PoW_Difficulty：本条消息要求的 PoW 算力难度（普通消息 / 公告区分）
PoW_Nonce：工作量证明随机数，用于验证 MST 手续费
TTL_Max_Hops：最大转发跳数，到达上限直接丢弃，防止广播风暴
Signature：发送方 Ed25519 签名（签名范围：头部全部明文字段，防止篡改元数据）
加密载荷（仅收发双方可解密，中继完全无法读取）
AES-256-GCM 加密，密钥来自 X3DH 协商会话密钥，包含：
消息正文文本
本地自定义过期 TTL（节点缓存超时自动销毁密文）
数据包核心约束
中间节点仅解析明文头部，无法解密载荷；缓存密文不影响安全，无泄密风险；
头部附带全局 SHA1，本地缓存 65536 条 Packet_SHA1 环形队列：
收到已存在哈希：不展示、不转发；
环形缓存满时，淘汰最早存入的哈希记录。
模块 4：广播排序规则（按你的要求修正 + 落地）
第一优先级：Timestamp_μs 微秒时间戳升序；
完全相同微秒时间戳：取整条数据包 SHA1 哈希二进制原始字节大小升序排列，全网所有节点排序结果完全一致，无本地随机分裂；
时间戳硬约束（修正你微秒过小问题，采用±500ms 毫秒偏移阈值）：
全网节点互相交换本地时钟偏移，统计全网平均基准时间；
消息时间戳与全网基准差值＞500ms，直接丢弃，拒绝广播转发；
选择 500ms 理由：普通家用 NTP 同步误差普遍 10~100ms，网络传输多跳延迟最高数百 ms，500ms 可过滤恶意篡改的未来 / 远古时间戳，又不会误判正常离线延迟消息。
模块 5：Alert 全局公告私钥体系（单一私钥，3 年后公开，无软分叉）
仅 1 组 Ed25519 Alert 密钥对，无多签；
权限硬编码限制：仅允许发送Alert_Flag=true全网广播消息，代码底层禁止该密钥执行任何路由、网络控制、身份修改操作；
消息形态：和普通全网广播格式完全一致，仅标记 Alert 标识，不会弹窗，作为普通信息流展示；
三年到期规则：
稳定运行满 3 年，项目公开 Alert 完整私钥；
用户客户端内置屏蔽指定 Sender_ID功能，用户可一键屏蔽 Alert 公钥 ID，不再接收任何公告消息；
所有历史 Alert 消息携带签名永久可校验，全网可追溯。
模块 6：MST 消息 PoW 工作量证明（抗 ASIC、动态难度、耗时控制）
6.1 算法选型（强抗 ASIC）
采用 RandomX 内存硬依赖算法，瓶颈为内存带宽而非单纯计算，ASIC 制造收益极低，普通 CPU/GPU 均可参与，符合去中心化要求。
6.2 算力耗时标准
普通用户单播 / 普通全网广播：PoW 计算耗时稳定≈2 分钟；
Alert 全网公告广播：PoW 计算耗时稳定≈20 分钟；
6.3 MST 代币与难度调节
每条消息完成 PoW 即销毁对应 MST，无增发，仅发送消息消耗；
全网每小时统计总 PoW 算力，动态调整难度：
全网算力上升 → 提高 RandomX 复杂度，维持 2min/20min 基准耗时；
全网算力下降 → 降低难度，避免普通用户无法发消息；
6.4 防垃圾消息约束
无 PoW 的数据包节点直接丢弃，不转发、不展示；大幅提高批量女巫广播成本。
模块 7：网络连接与抗封锁强化设计
7.1 种子节点机制
程序内置少量静态公网 IP 种子节点，首次启动仅用于接入主网；成功连上任意主网节点后，不再主动连接内置种子；
支持用户手动自定义添加任意多种子节点 IP / 洋葱地址，无数量限制。
7.2 极致抗封锁配套设计
数据包流量混淆：固定长度填充、随机转发延迟（10ms~3s），消除 DPI 协议特征；
双层传输兼容：明网 IPv4/IPv6 + Tor 洋葱节点双通路，自动切换连通性更好的链路；
无固定连接 DTN 存储 - 携带转发：数据包缓存本地等待邻居节点上线，转发延迟无上限（1 分钟～数天）；
泛洪流量限流：单节点每秒最大转发数据包配额，防止恶意节点带宽轰炸；
跳数上限控制：数据包 TTL 最大 30 跳，到达跳数直接销毁，杜绝无限循环广播。
三、现存微小漏洞 & 修复方案（必加补充项）
漏洞 1：SHA1 哈希存在理论碰撞风险（本地去重缓存）
修复：缓存存储 SHA1+SHA512 双哈希校验，双重去重，完全杜绝碰撞导致消息丢失。
漏洞 2：PoW 仅消耗算力，无 MST 代币总量管控
补充：MST 初始总量由创世 PoW 一次性产出，后续仅销毁不增发，总量恒定，避免通胀。
漏洞 3：节点长期离线，大量过期数据包占用内存
补充：每条载荷内置消息过期时间，本地定时扫描内存，自动删除超出 TTL 的密文数据包，释放内存。
漏洞 4：单一 Alert 私钥 3 年后公开，恶意节点可伪造公告刷屏
修复：Alert 消息额外叠加专属高难度 PoW（40 分钟），即使私钥公开，批量刷屏成本极高；用户一键屏蔽即可彻底隔绝。
漏洞 5：仅靠内存隔离，内核 dump、调试器可读取消息内存
补充：程序启动自动锁定内存禁止 dump，禁用 core dump，私有内存页设置不可调试权限，加固内存阅后即焚。
